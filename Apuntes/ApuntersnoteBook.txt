La comunicación entre un hijo un padre se realiza mediante métodos

El component parent tendrá un método y el hijo también tendrá otro método 

El método del HIJO enviará la información al método del PARENT 

 

PARENT COMPONENT 

 

const metodoPadre = () => { 

 

} 

 

Al estilo de props, debemos enviar esta información al component HIJO en su declaración.

Al recibir este método, no es un método cualquiera, es un método de recepción en props y se  

Ejecuta con otra sintaxis. 

 

HIJO 

 

let metodoHijo = props.metodoPadre; 

 

Cuando lo necesitemos, llamamos al método Hijo que, a su vez, llamará al método del padre 

 

<button onClick={ () => metodoHijo() }>Llamar a papa</button>

ESTADOS DE LA PAGINA (STATE) 

 

React no hace seguimiento a las variables de la página. 

Si deseamos que React realice seguimiento, debemos indicar que dichas variables serán especiales  

En el state de la página. 

 

Los estados de un component son varios: 

 

Cargar un component 

Update del component 

Destruir un component 

 

Dentro de estos estados podemos crear variables que estén asociadas a ellos, por ejemplo, variables asociadas  

Al render 

 

Para indicar este tipo de variables se realiza mediante state 

 

Dichas variables de estado tienen dos características: 

 

Get: Cuando recuperamos el valor de una variable 

Set: Cuando establecemos el valor de una variable 

 

Es como una variable con dos métodos internos generados. 

 

Para declarar este tipo de variables se utiliza una sintaxis "parecida" a deconstruir. 

 

const {dato1, dato2} = props; 

 

Para crear variables de state se utilizan corchetes en lugar de llaves. 

Dentro de la declaración se declara el nombre de la variable para el get y el nombre del  

Método para el set 

 

const [numero, setNumero] = useState(valor inicial) 

 

También para poder utilizar useState simplemente debemos hacer un import de react 

 

Vamos a crear un component llamado Contador en el que (por fin) veremos cambios en la página  

Mediante state

REACT CLASES JSX ES6 

 

Como ya dominamos React y somos máquinas en ello, vamos a visualizar otro tipo de sintaxis para  

Trabajar con React.  En lugar de utilizar Javascript con function, se utilizan clases denominadas ES6 

 

Mientras os voy contando, creamos un nuevo proyecto llamado reactclasesjsx 

 

Dentro de React podemos combinar perfectamente las dos sintaxis, la que hemos visto o la que  

Vamos a visualizar, es lo mismo.. 

 

De hecho, podríamos combinar dentro de un mismo proyecto los dos elementos, lo que no podemos hacer  

Es combinar las dos sintaxis dentro de un mismo component. 

 

React utiliza una sintaxis denominada JSX/ES6 que, en lugar de utilizar Javascript, utiliza un código más  

Parecido a Clases, como lenguajes C#, Java 

 

Sintaxis: 

 

class MiComponent extends Component { 

//LOS METODOS CAMBIAN SU SINTAXIS, YA NO  

//TIENEN DENOMINACION 

miMetodo = () => { … } 

 

//SE SEPARA EL CODIGO LOGICO DEL RENDER 

render() { 

return (<h1>Soy una clase component</h1>) 

} 

} 

 

export default MiComponent; 

 

Al tener sintaxis de clase, existen elementos conocidos en otros lenguajes sin tener que hacer  

Cosas "raras".  Por ejemplo, tenemos un constructor 

 

No se utiliza state de forma tradicional, ya no necesitamos useState 

 

Props sigue siendo exactamente igual, con la diferencia que es una variable interna de la clase  

Component, ya no necesito declarar props en ningún sitio. 

 

También, para acceder a los elementos de mi clase Component se utilizará la palabra clave this 

 

<MiComponent propiedad="valor"/> 

 

class MiComponent extends Component { 

this.props.propiedad 

} 

 

El funcionamiento de state es distinto.  No se utiliza useState.  En su lugar, se declara un objeto  

De tipo state = {} con todas las variables que quiero que sean utilizadas en el render 

 

class MiComponent extends Component { 

state = { 

velocidad: 0,  

estado: false,  

coche: { 

marca: "Audi", 

modelo: "Q8" 

} 

} 

} 

 

Posteriormente, dentro de mi clase, puedo acceder a cualquier objeto de state simplemente utilizando  

this.state.dato 

 

{this.state.velocidad} 

{this.state.coche.marca} 

 

STATE es de solo lectura, no podemos modificar sus datos directamente, solamente acceder a ellos. 

 

Para poder modificar los datos de cualquier elemento del state, simplemente se utiliza un método  

Del component llamado setState 

 

this.setState( velocidad: 200 ) 

 

Vamos a realizar el ejemplo del contador que hemos hecho antes con el código JS. 

 

 

Los components tendrán extensión JSX a partir de ahora. 

 

Creamos una carpeta llamada components dentro de src y un fichero llamado Contador.jsx 

 

 

CONTADOR.JSX

class Contador extends Component {

DIBUJOS COMPLEJOS HTML 

 

Como hicimos el viernes, podemos realizar dibujos complejos dentro de nuestro código HTML 

 

 

Solamente podemos utilizar un return dentro de cualquier método con dibujos dinámicos. 

¿Qué sucede si necesitamos realizar dibujos más complejos como, por ejemplo, una lista o  

Una tabla HTML? 

 

Tenemos dos posibilidades para poder realizar código HTML algo más complejo: 

 

Un método que genere código HTML y lo almacene dentro de un objeto complejo como,  

Por ejemplo un Array. 

 

 

Vamos a crear un nuevo component llamado DibujosComplejosArray.jsx 

 

DIBUJOSCOMPLEJOSARRAY.JSX 

 

import { Component } from "react"; 

class DibujosComplejosArray extends Component { 

    dibujarNumeros = () => { 

        let lista = []; 

        for (let i = 1; i <= 7; i++){ 

            var num = parseInt(Math.random() * 120) + 1; 

            //AÑADIMOS CADA NUMERO A LA LISTA CON HTML 

            lista.push(<li>{num}</li>); 

        } 

        return lista; 

    } 

    render () { 

        return (<div> 

            <h1>Dibujos complejos Array</h1> 

            <ul> 

                {this.dibujarNumeros()} 

            </ul> 

        </div>) 

    } 

} 

export default DibujosComplejosArray; 

 

Al visualizar, podremos comprobar que hace el dibujo, pero tenemos "errores" dentro de React 

 

 

Al realizar dibujos dinámicos con múltiples elementos "iguales", React necesita que cada elemento 

Dinámico tenga un ID único entre ellos.  Cada elemento de contener una key 

 

 

Utilizar código lógico dentro del render.  Esto utiliza una sintaxis especial de React, nada  

Que ver con JS ni nada de eso. 

 

Dentro del render no se utilizan métodos "tradicionales" de programación, como if o for,  

Se utiliza otro tipo de sintaxis. 

 

Para poder utilizar sintaxis React dentro de render, se utilizan las llaves, de esa forma indicamos  

Que deseamos escribir código lógico en lugar de código HTML 

 

render() { 

return (<div> 

<h1>Titulo</h1> 

{ 

//CODIGO LOGICO DE REACT 

} 

<p>Código HTML</p> 

</div>); 

} 

 

Como estamos recorriendo un objeto complejo (Array) debemos realizar un bucle dentro de React. 

Para ello se utilizan los métodos de los objetos,  por ejemplo, Array contiene un método llamado  

map que nos permite recorrer sus elementos. 

 

Si deseamos recorrer un conjunto: map(objeto, index) 

 

Array.map(objeto, index) { 

//objeto es cada elemento dentro del Array 

} 

 

Cuando utilizamos código dinámico dentro del render, siempre debemos incluir un return,  

Si no ponemos return, compila estupendamente, pero no dibuja nada y me vuelvo loco. 

 

Vamos a realizar un component para esta nueva funcionalidad. 

 

Dibujaremos nombres dentro del render 

Tendremos un botón que creará un nuevo nombre dentro del Array lo dibujará 

Necesitamos que el Array esté dentro de state 

 

 

Creamos un nuevo component llamado DibujosComplejosRender.jsx 

 

DIBUJOSCOMPLEJOSRENDER.JSX 

 

 

import { Component } from "react"; 

class DibujosComplejosRender extends Component{ 

    //NECESITAMOS UN ARRAY EN STATE PARA  

    //IR GENERANDO NUEVOS ELEMENTOS AL PULSAR UN BOTON 

    state = { 

        nombres: ["Diana", "Antonia", "Adrian", "Lucia"] 

    } 

    generarNombre = () => { 

        //PODEMOS UTILIZAR DIRECTAMENTE EL METODO DEL ARRAY push 

        //SI ES UN OBJETO SIMPLE (string, int) NO PODEMOS ASIGNAR 

        this.state.nombres.push("NUEVO NOMBRE"); 

        //SI NO REASIGNAMOS EL VALOR MEDIANTE setState, NO LO VEREMOS 

        this.setState({ 

            nombres: this.state.nombres 

        }) 

    } 

    render() { 

        return (<div> 

            <h1>Dibujos complejos render</h1> 

            <button onClick={this.generarNombre}> 

                Generar nombre 

            </button> 

            { 

                //ESTO ES CODIGO JSX DE REACT 

                this.state.nombres.map((nombre, index) => { 

                    //ESTE CODIGO NECESITA UN RETURN PARA EL RENDER 

                    return (<h4 style={{color: "blue"}} key={index}> 

                        {nombre} 

                        </h4>) 

                }) 

            } 

        </div>) 

    } 

} 

export default DibujosComplejosRender;

PRACTICA COMUNICACIÓN COMPONENTS 

 

Tendremos dos components, un Padre y un Hijo. 

En el component Padre, debemos cargar (al inicio) múltiples números aleatorios (NO) 

 

Cada número aleatorio, dibujará un component Hijo al que enviaremos el valor del número  

Aleatorio generado. 

 

El padre, también tendrá la posibilidad (mediante un botón) de crear más números aleatorios  

(como hemos hecho con el nombre del ejemplo anterior) 

 

En el component Hijo, tendremos un botón llamado Sumar número que, al pulsar,  

Realizará una suma en el padre, es decir, cada hijo, al pulsar, enviará su número al padre y  

El padre irá haciendo la suma de cada número pulsado 

 

Los components se llamarán PadreNumeros.jsx e HijoNumero.jsx 

 

 

PADRENUMEROS.JSX

        this.state.numeros.push(aleat);

            numeros: this.state.numeros 

        }) 

    } 

    render() { 

        return (<div>

            </h2>

                Generar número 

            </button> 

            { 

                this.state.numeros.map((num, index) => { 

                    return (<HijoNumero numero={num} key={index}

CONDICIONALES REACT 

 

Dentro del lenguaje React estamos visualizando múltiples códigos, todo depende dónde escribimos 

 

En este momento, hablamos de condicionales dentro del render() 

 

Existe una sintaxis especial para realizar condicionales: 

 

 

Sintaxis para ELSE 

 

 

Tenemos sintaxis para IF, ELSE IF y ELSE 

 

 

Esta funcionalidad la vamos a visualizar mediante un ejemplo "parecido" a lo que hemos hecho con  

Deportes. 

Utilizaremos objetos en lugar de simples string. 

Tendremos un padre para dibujar Comics.  Cada hijo recibirá un comic para un dibujo. 

 

El hijo podrá tener la funcionalidad de Favorito y podremos eliminar un comic del conjunto,

Solamente dibujaremos el favorito cuando exista un favorito, mediante el render.

REACT ROUTING 

 

Creamos un nuevo proyecto llamado reactroutesforms 

 

Dentro de los frameworks SPA no siempre tenemos los elementos accesibles, es decir, las librerías

Para instalar librería en los frameworks se utiliza npm 

 

React no trae de serie las librerías para poder realizar navegación entre components, cuando  

Hablamos de navegación, estamos hablando de Links. 

 

 

La navegación tradicional lo hace mediante páginas Web, pero SPA lo hace entre components. 

 

La forma de trabajar es habilitar "un lugar" dónde deseamos que se dibujen los components  

Que vengan de la navegación. 

 

 

Este concepto se denomina Routing 

 

Para poder aplicar este concepto debemos montar una serie de elementos: 

 

Necesitamos una clase que contenga todos los mappings de rutas a components.

A partir de esta clase, en index.js o en cualquier component que deseemos como  

Principal, debemos indicar el "lugar" dónde se dibujarán los components de la  

Navegación:  <Router/> 

 

<Ruta path="/" component={HomeComponent}/> 

<Ruta path="/comics" component={ComicsComponent}/> 

 

http://localhost:3000/ --> HomeComponent 

http://localhost:3000/comics --> ComicsComponent

CONJETURA DE COLLATZ 

 

Es una teoría que generó un Matemático llamado Collatz y que dice lo siguiente: 

 

"Todo número natural siempre llegará a ser 1 siguiendo dos patrones": 

 

Si el número es par, se divide entre 2 

Si el número es impar se multiplica por 3 y se suma 1 

 

6, 3, 10, 5, 16, 8, 4, 2, 1 

 

Creamos un nuevo component llamado Collatz.jsx

CICLO DE VIDA DE UN COMPONENT 

 

El ciclo de vida de un component nos puede permitir crear elementos estáticos y  

Dinámicos. 

Ahora mismo todos los elementos son dinámicos en el render(). 

 

Como nos ha pasado en algún momento, si llamamos a un método en el render()  

Y dicho método, modifica el render, tenemos un maravilloso bucle infinito. 

 

El problema no está en el código, está en el CUANDO 

 

Tenemos una serie de ciclos de vida, como métodos de un Component que nos  

Permiten saber CUANDO van a ser llamados. 

 

ComponentDidUpdate(): Se ejecuta cuando el RENDER cambia 

ComponentDidMount(): Se ejecuta ANTES de dibujar el component 

ComponentWillUnMount(): Se ejecuta cuando el component es eliminado del  

Parent 

 

Tenemos otro método, que es el constructor del component. 

Se utiliza solamente para inicializar los valores de las variables. 

 

class Component { 

constructor() { 

this.dato = this.props.algo; 

} 

} 

 

REACT SERVICIOS 

 

Mientras os voy contando, creamos un nuevo proyecto llamado reactservices 

 

Dentro de los Frameworks Front, "solamente" podemos consumir datos desde  

Servicios Api/Rest. 

 

Los servicios Api/Rest son el motor de TODO.  La información, cuando es expuesta  

En Internet siempre utiliza Servicios. 

Estos servicios no dejan de ser información, que puede ser consumida o modificada,  

Todo depende del servicio creado/generado. 

 

Existen dos formatos estándar para la información de los servicios: JSON/XML 

 

Dentro de los api tenemos múltiples métodos de acceso/consumo: 

 

GET:  Sirve para recuperar datos 

POST: Sirve para crear elementos en el Api o también para enviar  

Información cifrada y recuperar información (login) 

PUT: Se suele utilizar para modificar. 

DELETE: Se utiliza para eliminar datos del Api. 

 

Tenemos varias formas de leer contenido de un Api. 

 

Algunas son nativas y otras debemos instalarlas. 

 

FETCH: Esto es nativo de JS, no necesitamos instalar nada, directamente le  

Indicamos que vamos a leer y adelante. 

AXIOS: Es una de las librerías más demandadas en los frameworks de Front. 

Va muy fluida y se puede utilizar en múltiples Fronts. Pero debemos instalarla  

En los proyectos. 

 

Las peticiones a un Api son asíncronas, es decir, sabemos cuándo hacemos la petición,  

Pero no sabemos cuándo nos dará la respuesta. 

Como son asíncronas, dichas peticiones debemos realizarlas mediante promesas que,  

Son bloques de código en espera de una respuesta. 

 

console.log("Antes") 

fetch('Url api', (data) => { 

console.log("Leyendo"); 

}) 

console.log("Después") 

 

ANTES 

DESPUES 

LEYENDO

npm install --save axios

VARIABLES GLOBALES REACT 

 

Las variables globales nos permiten unificar, en un solo lugar, múltiples datos para todos  

Los components compartidos, es decir, todos los components tendrán acceso a dichas  

Variables. 

Las variables pueden ser de lectura o escritura, aunque en nuestro ejemplo exacto, serán  

Para almacenar las Urls de los apis. 

De esta forma, si tenemos en un fichero global las urls y se cae el servidor, podríamos cambiar  

En un solo lugar el valor del Api y será modificado en cada petición. 

 

Al no ser un component, se pone como extensión JS y se suele llamar Global.js 

 

Sintaxis: 

 

var Global = { 

urlApi1: "https://…", 

urlApi2: "https://…", 

Token: "jofdjkljfsd", 

} 

 

export default Global; 

 

Sobre src, creamos un nuevo fichero llamado Global.js

COMUNICACIÓN COMPONENTS API 

 

Esta teoría ya la hemos visto, es decir, cómo se comunican los components mediante  

Props ( Padre --> Hijo) o mediante props methods (Hijo --> Padre) 

 

Todo parece lo mismo, pero con servicios, podría ser que no… 

 

Vamos a realizar una aplicación para comprobar si la comunicación es igual si lo hacemos  

Con un Coche/Deporte o si lo hacemos con un Servicio. 

 

Vamos a utilizar un ejemplo que hemos realizado hoy, pero lo vamos a modificar completamente  

En su funcionalidad. 

 

Hablamos de Empleados y Departamentos 

En lugar de tener todo en un component, vamos a separar las piezas. 

 

Por un lado, tendremos un component para dibujar los Departamentos y su formulario 

 

<Departamentos/> 

Por otro lado, tendremos un component para dibujar los empleados de un departamento  

Seleccionado.  Utilizaremos este component desde el Padre <Departamentos/> 

 

<Empleados iddepartamento="10"/> 

 


 

Sobre src/components, creamos una nueva carpeta llamada maestrodetalle 

 

Dentro de la carpeta, creamos dos components:  DepartamentosComponent y  

EmpleadosComponent 

 

Al montar la solución, podremos comprobar que solamente envía el dato UNA vez con  

componentDidMount.  Esto es debido a que el component ya está dibujado y no vuelve a repetir  

La acción de montar. 

 


 

Necesitamos otro método para esta funcionalidad. 

Tenemos un método llamado componentDidUpdate() que se ejecuta cuando algo  

Es modificado en el component, aunque no sea dibujado 

 

Nota: Nada de llamar al Api de empleados 

 

Vamos a escribir un código en este nuevo método para saber cómo funciona 

 


 

Veremos un maravilloso error al ejecutar nuestro component. 

Queremos capturar el Id del departamento y eso ya lo hemos hecho mediante  

Props y componentDidUpdate() 

El problema está en que y queremos dibujar el Id del departamento cuando venga. 

Cuando realizo un dibujo con state en la página, está ejecutando el render y, al ejecutar  

El render, está ejecutando un Update 

 


 

Necesitamos "saber" cuando está cambiando Update. 

Dentro del método componentDidUpdate() tenemos la posibilidad de recibir  

Props y, concretamente, podemos recibir el antiguo props y el nuevo props. 

De esta forma, podemos decidir qué hacer con PROPS y su comportamiento en el  

Dibujo. 

 

 

Ya tenemos "algo" por lo que preguntar 

 

 

A continuación, vamos a modificar el código para dibujar en state solamente cuando  

Props tenga un cambio. 

 

Nota: Nunca cambiaremos state en componentDidUpdate() sin un IF

RUTAS CON PARAMETROS 

 

Necesitamos instalar rutas dentro de nuestro proyecto 

 

npm install --save react-router-dom 

 

Hemos trabajado con rutas dentro de nuestros proyectos, dichas rutas son estáticas, es decir,  

No reciben ningún parámetro. 

 

 

El siguiente paso a realizar es utilizar rutas con parámetros dinámicos dentro de nuestro proyecto. 

 

Si deseamos trabajar con parámetros, debemos hacerlo mediante parámetros declarados en Router.js 

 

Las rutas se envian de forma mapeada: 

 

CLASICA 

 

https://localhost:3000/cine?idpeli=1 

 

MAPPING 

 

https://localhost:3000/cine/1 

 

Los parámetros deben estar declarados mediante dos puntos y con un name en la etiqueta <Route/> 

 

<Route path="/cine/:idpeli" element={<Cine/>}/> 

 

Por supuesto, podemos enviar más parámetros siguiendo el mapping: 

 

<Route path="/cine/:idpeli/:otroparametro" element={<Cine/>}/> 

 

Los parámetros no pueden ser enviados mediante props: 

 

<Route path="/cine/:idpeli" element={<Cine idpeli="1"/>}/> 

 

Para poder recuperar el valor, si que lo haremos mediante props, pero no podemos enviar  

Props dentro de el atributo element 

 

Debemos declarar un método, dentro de Router.js, que resuelva los parámetros recibidos y devuelva  

La etiqueta estructurada mediante props. 

Los parámetros, dentro del método, deben ser recuperados mediante useParams() 

 

El nombre de los parámetros se recupera mediante deconstrucción y su nombre es importante. 

 

EJEMPLO DE UN METODO DE PATH 

 

 

Por último, en la etiqueta Route, enviaremos el nombre del método al atributo element 

 

<Route path="/cine/:idpeli/:otroparametro" element={<getParametrosCine/>}/>

POST CON AXIOS 

 

Un método POST de un Api sirve para enviar información al servidor. 

Dicha información puede ser tratada en el servidor de múltiples formas por ejemplo, para  

Validación o para insertar. 

 

Los datos internos de post llegan cifrados al servidor back. 

 

En los ejemplos que vamos a probar, utilizaremos POST para insertar elementos en el servidor. 

 

Vamos a probar el siguiente método del Api, que inserta internamente un Hospital en el  

Server 

 


 

Debemos enviar la información en formato JSON, teniendo en cuenta case sensitive y el  

Tipado de los datos del JSON 

 


 

Existen datos de tipo string y datos de tipo int. 

Si enviamos algún dato que no se corresponda, nos dará un error con status code 415 

 

Axios trabaja directamente con objetos JSON que es su formato predeterminado. 

 

No debemos convertir nada, simplemente utilizar el objeto que hemos declarado en código. 

 

Sintaxis: 

 

let hospital = { 

idHospital: 19, 

nombre: "", 

…. 

} 

 

El método POST/PUT de axios nos solicita dos parámetros: 

 

Url de acceso al servicio 

Objeto a enviar (data) 

 

Vamos a crear un nuevo component para crear hospitales. 

Creamos un nuevo component llamado CreateHospital.jsx

Mediante <Navigate to="/path"/>

Agregamos una variable llamada status a nuestro state
